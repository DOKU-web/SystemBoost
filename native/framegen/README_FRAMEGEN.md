# SystemBoost FrameGen v0.6

화면 캡처 기반 프레임 생성 + 업스케일링 모듈입니다. 게임 프로세스에 주입하지 않고, 메모리도 읽지 않습니다. 입력은 OS 화면 캡처(Windows.Graphics.Capture 또는 DXGI Desktop Duplication)만 사용하고, 출력은 클릭이 통과되는 최상단 창에 표시합니다.

> 이 버전은 기존 v0.5 `framegen.cpp`를 보지 않고 새로 작성했습니다. 교체 방법은 아래 "v0.5에 합치기"를 보세요.

## v0.6에서 바뀐 점

| # | 항목 | 구현 |
|---|---|---|
| 1 | 화질 | 양방향(A→B, B→A) 블록 모션 추정, 피라미드 계층 탐색(큰 움직임), 3×3 중앙값 필터, 서브픽셀 보정, 이전 프레임 움직임을 후보로 재사용(시간적 안정성) |
| 2 | 가려짐 처리 | 앞뒤 벡터 일치 검사로 방향별 신뢰도를 계산하고, 보이는 쪽 프레임에서 가져옴 |
| 3 | 배수 | 자동(모니터 주사율 기준, 최대 8배) + 2·3·4·6·8배 고정 + 끄기(업스케일만) |
| 4 | 간격 균일화 | 화면 시계 방식 페이서: 표시 시각에서 일정 지연 D를 뺀 게임 시점을 보간해서 원본 프레임 간격 흔들림이 화면에 그대로 드러나지 않음 |
| 5 | 깨짐 줄이기 | HUD·UI처럼 안 움직이는 픽셀은 원본 유지 + 움직이는 배경이 HUD를 끌고 가지 않게 차단, 장면 전환 감지 시 생성 생략, 화면 밖 샘플은 신뢰도 0 |
| 6 | 업스케일링 | 테두리 번짐 방지 바이큐빅 + 대비 적응형 선명화(0~1), 화면 비율 유지(레터박스), 확대 위치에 커서를 다시 그림 |
| 7 | 듀얼 GPU | 프레임 생성을 내장 그래픽(또는 지정 GPU)에서 실행. WGC는 OS가 프레임을 넘겨주고, DXGI 캡처는 직접 복사(전송 시간 측정·표시) |

## 빌드 (Windows)

Visual Studio 2022 + Windows SDK 10.0.19041 이상.

```
cd native\framegen
cmake -B build -A x64
cmake --build build --config Release
```

결과: `build\Release\sb_framegen.exe` + `build\Release\shaders\*.cso`. 앱 배포 폴더의 `native\framegen\`에 둘 다 복사하세요. fxc를 못 찾으면 `.hlsl`을 복사하고 실행 시 컴파일합니다(시작이 1초쯤 느려짐).

## 실행 옵션

```
sb_framegen.exe --hwnd 0x1234AB [옵션]
  --mode auto|x2|x3|x4|x6|x8|off   기본 auto. off = 프레임 생성 없이 업스케일만. 고정 배수도 주사율을 넘지 않음
  --max-mul 2..8             auto 모드 최대 배수 (기본 4). 경계에서는 25%까지 넘을 수 있음
  --quality low|performance|balanced|quality
                             분석 해상도 1/8, 1/4, 1/2, 1/2 + 정밀 탐색 2회
  --upscale                  게임 창을 그 모니터 크기로 확대 (비율 유지)
  --sharpness 0..1           업스케일 선명화 (기본 0.5)
  --gen-gpu same|igpu|<번호>  프레임 생성 GPU (번호는 --list-gpus 결과)
  --capture wgc|dxgi         기본 wgc
  --capture-cursor           (업스케일 아닐 때) 캡처 이미지에 커서 포함
  --no-clip-cursor           업스케일 시 커서 가두기 끄기
  --list-gpus                GPU 목록 JSON 출력 후 종료
```

### 앱과의 통신 (한 줄에 JSON 하나)

stdout:
```json
{"type":"ready","capture":"wgc","genGpu":"...","displayGpu":"...","refreshHz":143.99,...}
{"type":"stats","srcFps":47.9,"outFps":143.8,"multiplier":3.00,"refreshHz":143.99,
 "delayMs":23.9,"addedLatencyMs":21.4,"genMs":0.81,"analyzeMs":1.42,"transferMs":0,"late":3,"skipped":0}
{"type":"fit","quality":"performance"}
{"type":"warning"|"error","msg":"..."}
{"type":"exit"}
```
`fit`: 출력 시점을 3초 동안 계속 놓쳐서 엔진이 스스로 낮췄다는 뜻입니다. 품질을 한 단계씩 내리고(`quality`), 저사양에서도 밀리면 출력을 약 4분의 1 줄이고(`maxOut`), 출력이 원본의 1.25배 이하가 되면 프레임 생성을 멈춥니다(`stopped`). 다음 시작 때는 원래 설정으로 돌아갑니다.

stdin: `mode x3`, `sharp 0.4`, `enable`, `disable`, `quit`. stdin이 닫히면(앱 종료) 스스로 종료합니다.

화면에 보여 줄 값:
- **원본 FPS → 출력 FPS**: `srcFps`, `outFps`
- **추가 지연**: `addedLatencyMs`. 생성 없이 원본을 바로 보여 줄 때보다 늘어난 지연의 추정치예요. 측정값으로 표시하고 "지연 0" 같은 문구는 쓰지 마세요.
- **GPU 시간**: `genMs`(출력 1장), `analyzeMs`(원본 1장 분석)
- **늦은 프레임**: `late`가 계속 늘면 게임 FPS가 불안정한 상태예요. 게임 내 FPS 제한을 권장하세요.

## v0.5에 합치기

1. 기존 `native/framegen/`을 백업하고 이 폴더로 교체합니다.
2. 기존 framegen의 실행 인자·출력 형식이 위 프로토콜과 다르면, WPF 쪽 호출 코드를 `integration/FrameGenProcess.cs`로 바꿉니다. 이 클래스는 프로세스 시작, 통계 이벤트, 명령 전송, 비정상 종료 시 커서 복구까지 처리합니다.
3. 설정 화면에 추가할 항목: 배수(자동/2/3/4/끄기), 최대 배수, 품질, 업스케일 켜기 + 선명도, 프레임 생성 GPU(`ListGpusAsync` 결과로 목록).
4. 설치 프로그램(인스톨러)에 `sb_framegen.exe`와 `shaders\*.cso`를 넣고 코드 서명 대상에 포함합니다.
5. 단축키: 앱의 전역 단축키에서 `Enable(true/false)`를 호출하면 됩니다.

## 측정 결과 (이 환경에서 측정)

모두 `tests/run_all.sh`로 다시 만들 수 있습니다. 결과 원본은 `tests/results/`에 있습니다.

### 1) 보간 화질: 정답 프레임과의 PSNR (dB, 높을수록 정답에 가까움)

합성 장면(640×360, 질감 + 도형 + 고정 HUD)에서 t=1/3, 1/2, 2/3 평균입니다. 정답은 같은 장면을 그 시점으로 직접 렌더링한 이미지입니다.

| 장면 | 단순 섞기 | 단순 블록 매칭* | v0.6 |
|---|---|---|---|
| 작은 이동 (4px/프레임) | 31.9 | 35.5 | **41.4** |
| 큰 이동 (40px/프레임) | 16.2 | 16.1 | **25.8** |
| 줌 | 24.9 | 27.3 | **31.8** |
| 가려짐 (물체가 배경 앞을 지나감) | 24.9 | 26.4 | **29.8** |
| HUD 영역만 | 99 (그대로) | 16~28 | **99 (그대로)** |
| 장면 전환 감지 | - | - | 감지됨, 생성 생략 |

\* 단순 블록 매칭 = 한 해상도, 한 방향, 가려짐 처리 없는 방식. **실제 v0.5 코드가 아니라** 흔한 1차 구현을 흉내 낸 비교 기준입니다. v0.5와의 실제 비교는 PC에서 해야 합니다.

### 2) 셰이더 = 참조 구현 확인

실제 HLSL 셰이더를 SPIR-V로 컴파일해 소프트웨어 Vulkan(lavapipe)에서 실행하고, 같은 입력의 CPU 참조 결과와 비교했습니다. 5개 장면 × 3시점, 시간 후보 경로 2건, 업스케일 1건 모두 일치합니다(움직임 벡터 100% 일치, 출력 차이 1e-5 미만). D3D11 실제 빌드는 중간 텍스처를 16비트로 저장해서 아주 작은 차이는 생길 수 있습니다.

### 3) 프레임 간격 (144Hz 화면, 원본 FPS에 ±1.5ms 흔들림 + 3% 확률로 25ms 끊김을 넣은 20초 시뮬레이션)

| 상황 | 방식 | 움직임 흔들림 (ms) | 반복된 화면 | 버려진 프레임 | 평균 지연 (ms) | 출력 FPS |
|---|---|---|---|---|---|---|
| 48fps, 자동 | 고정 비율(1차 구현식) | 5.23 | 9.4% | 5.7% | 21.1 | 130 |
| 48fps, 자동 | **v0.6** | **2.58** | **0%** | **0%** | 24.3 | **144** |
| 40~70fps 변동, 자동 | 고정 비율 | 7.04 | 12.8% | 7.3% | 19.0 | 126 |
| 40~70fps 변동, 자동 | **v0.6** | **4.70** | **0%** | **0%** | 22.2 | **144** |
| 30fps, 4배 | 고정 비율 | 4.83 | 19.7% | 1.0% | 32.6 | 116 |
| 30fps, 4배 | **v0.6** | **3.02** | 16.9% | **0%** | 40.3 | 120 |

움직임 흔들림 = 화면에 표시되는 시각과 그 화면이 보여 주는 게임 시점의 차이가 얼마나 들쭉날쭉한지(표준편차). 0이면 완전히 고른 움직임입니다.

**지연은 v0.6이 3~8ms 더 깁니다.** 고른 간격을 만들려면 모든 프레임에 같은 지연(원본 1프레임 + 처리 시간)을 줘야 하기 때문입니다. 대신 화면 반복·버려지는 프레임이 없어져서 끊김이 줄어듭니다. 30fps 4배에서 반복 화면 16.9%는 120fps 출력을 144Hz 화면에 띄우는 데서 생기는 것이라 자동 모드를 권장합니다.

### 4) 업스케일 (원본 해상도 이미지를 줄였다가 다시 키워서 원본과 비교)

| 배율 | 방식 | PSNR | 선명도 (원본=1.00) |
|---|---|---|---|
| 1.5배 | 바이리니어 | 39.16 | 0.96 |
| 1.5배 | v0.6 선명도 0.5 | **40.46** | **1.01** |
| 2배 | 바이리니어 | 32.69 | 0.92 |
| 2배 | v0.6 선명도 0.5 | **32.95** | **0.98** |

업스케일링은 없던 디테일을 만들지 못합니다. 바이리니어보다 선명하고 경계 번짐이 적은 정도이고, 2배 이상에서는 차이가 작습니다.

## 한계 (사용자 안내 문구에 반영 필요)

- **지연**: 보간은 다음 프레임을 기다려야 해서 원본 1프레임 + 처리 시간만큼 지연이 생깁니다. 원본 30fps면 약 35~40ms. 경쟁 게임에는 권장하지 않습니다.
- **테두리 없는 창 / 창 모드 필요**: 독점 전체 화면은 캡처되지 않습니다.
- **반투명 HUD**: 완전히 고정된 HUD는 보호되지만, 반투명 HUD 아래로 배경이 움직이면 그 부분은 일부 번질 수 있습니다.
- **빠른 회전, 큰 가려짐**: 한 번에 찾을 수 있는 이동 거리(1080p 균형 품질 기준 프레임당 약 ±100px, 이전 움직임 후보가 맞으면 더 큼)를 넘으면 깨짐이 보일 수 있습니다.
- **업스케일 + 마우스**: 실제 커서는 게임 창 안에 갇히고 확대 위치에 다시 그려집니다. 그래서 마우스 이동이 확대 배율만큼 빠르게 느껴질 수 있습니다. 게임이 자체 커서 이미지를 쓰는 경우(시스템 커서가 아닌 경우) 커서가 두 개로 보일 수 있습니다.
- **듀얼 GPU**: 모니터가 외장 그래픽에 꽂혀 있으면 생성 결과를 다시 외장으로 넘기는 복사가 생겨서 이득이 줄거나 손해일 수 있습니다. 모니터가 생성 GPU 쪽에 연결된 구성에서 효과가 큽니다. 켜기 전후로 반드시 측정하세요.
- **다중 모니터 주사율**: 주사율이 다른 보조 모니터에서는 vblank 위상을 DWM 기준으로 잡아서 간격이 덜 정확할 수 있습니다.

## 안티치트 안전 설계

- 게임 프로세스 열기(OpenProcess), DLL 주입, 메모리 읽기·쓰기, DirectX/Vulkan 후킹 없음
- 입력: OS 캡처 API만 사용. 출력: 별도 창(클릭 통과, 포커스 안 가져감)
- 자기 출력 창은 캡처에서 제외(WDA_EXCLUDEFROMCAPTURE). 녹화·방송 프로그램에는 원본 게임 화면이 잡힙니다.
- 업스케일 모드에서 바꾸는 시스템 상태(커서 모양, 커서 가두기)는 정상 종료, 콘솔 종료, 크래시 경로에서 복구하고, 프로세스가 강제 종료되면 앱(FrameGenProcess.cs)이 복구합니다.

## PC에서 확인할 것 (스팀 출시 전 필수)

1. **빌드**: MSVC로 빌드 → `--list-gpus`가 GPU 목록을 출력하는지
2. **기본 동작**: 테두리 없는 창 모드 게임에서 `--mode x2` → 오버레이가 게임 위에 정확히 겹치는지, 클릭·키 입력이 게임으로 가는지, 알트탭 시 오버레이가 사라지는지
3. **페이싱**: 게임 FPS를 48로 제한하고 자동 모드 → `outFps`가 주사율에 가까운지, `late`가 거의 안 늘어나는지
4. **지연 측정**: 같은 장면에서 끄기/2배/자동 각각 `addedLatencyMs` 기록. 가능하면 고속 촬영(240fps 폰 슬로모션)으로 클릭→화면 변화 시간 비교
5. **화질**: 빠른 회전, HUD, 자막, 장면 전환(로딩)에서 깨짐 확인. 스크린샷이 아니라 녹화로 확인(오버레이는 캡처에서 제외되므로 폰 촬영 필요)
6. **업스케일**: 1280×720 창 모드 → 모니터 전체로 확대, 커서 위치·클릭 정확도, 종료 후 커서 모양 원래대로인지(작업 관리자로 강제 종료해서도 확인)
7. **듀얼 GPU**: `--gen-gpu igpu` 켜기 전후 게임 FPS와 `transferMs`, `genMs` 비교. 효과 없으면 설정 화면에서 숨기기
8. **안티치트**: EAC·BattlEye 게임 1~2개에서 실행해 경고나 튕김이 없는지
9. **장시간**: 1시간 실행 후 메모리 사용량이 늘지 않는지

## 코드 검토 반영 (Windows 전용 부분)

여기서는 Windows 코드를 실행할 수 없어서 별도 검토를 거쳤고, 아래를 고쳤습니다.
- 고해상도 배율(125%, 150% 등) 모니터에서 캡처 영역이 어긋나는 문제 → 프로세스를 모니터별 DPI 인식(PMv2)으로 설정
- 업스케일 + 끄기 모드에서 알트탭 후 해제된 커서 텍스처를 쓰는 크래시 → 커서 뷰를 참조 카운트로 보관
- 업스케일 배율이 1일 때 커서가 안 보이는 문제 → 업스케일 모드에서는 항상 커서 합성 패스 실행
- WGC 초기화 실패 시 오류 메시지 없이 종료 → DXGI 캡처로 자동 전환 + 모든 예외에서 오류 출력·커서 복구
- GPU 리셋(TDR) 후 마지막 화면이 게임 위에 멈춰 있는 문제 → 오버레이 숨기고 오류로 종료
- 게임 창을 다른 모니터로 옮기면 DXGI 캡처가 옛 모니터에 남는 문제 → 모니터 변경 감지 후 다시 연결
- 종료 시 표준 입력 대기 때문에 프로세스가 남을 수 있는 문제 → 정리 후 바로 프로세스 종료
- DXGI 캡처가 게임과 무관한 화면 갱신을 프레임으로 세는 문제 → 변경 영역이 게임 영역과 겹칠 때만 사용
- 그 밖에: 선명도 설정이 창 크기 변경 시 초기화되던 문제, 알트탭 복귀 시 오래된 프레임 표시, 게임이 건 커서 가두기를 풀어 버리던 문제, 커서 핸들 누수 등

남은 확인 사항(PC에서):
- **내장 그래픽 자동 판별**: 전용 메모리 512MB 미만을 내장으로 봅니다. AMD APU처럼 예약 메모리가 큰 경우 틀릴 수 있으니, 설정 화면에서는 `--list-gpus` 목록에서 직접 고르게 하는 것을 권장합니다.
- **MSVC + 오래된 Windows SDK**: SDK 19041의 C++/WinRT 헤더가 C++20에서 컴파일 오류를 내면 NuGet `Microsoft.Windows.CppWinRT` 패키지나 최신 SDK를 쓰세요.
- **Windows 10 1803 이전**: 고해상도 타이머가 없어 페이싱이 부정확합니다. 최소 지원을 Windows 10 2004로 잡으세요(WGC도 2004 필요).

## 라이선스

모든 코드와 셰이더는 이 프로젝트용으로 새로 작성했습니다. 외부 코드(Lossless Scaling, AMD FSR, NVIDIA NIS 등)는 쓰지 않았습니다.
