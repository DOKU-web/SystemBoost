# 라이선스 서버 + 관리자 대시보드

Cloudflare Workers + KV (무료 플랜으로 충분). 결제는 판매자가 직접 받고(본인 결제 페이지 링크),
결제를 확인한 뒤 대시보드에서 키를 발급하면 구매자 앱에 팝업으로 뜹니다.

결제 방식은 두 가지이고 함께 켤 수 있습니다. 둘 다 열려 있으면 구매자가 앱에서 '카드 결제'와 '계좌이체 · 직접 결제' 중에 고릅니다.

**계좌이체 · 직접 결제**: 대시보드에 결제 링크를 넣으면 켜짐. 사장님이 확인하고 승인
```
앱 '결제하기' → 주문 코드 SB-XXXX-XXXX + 결제 링크 열림                       [신청 중]
구매자: 결제 메모에 코드 → 앱에서 입금자명 적고 '결제했어요'                  [결제 확인 요청]
사장님: 대시보드 '결제 신청'에서 확인 → '승인'(키가 무작위로 생성돼 앱에 팝업) [승인]
                                    또는 '거절'(사유가 구매자 앱에 표시)       [거절]
```
**카드 결제 (Lemon Squeezy)**: 대시보드 '카드 결제'를 테스트/실판매로 켜면 열림. 결제가 확인되면 사람 손 없이 키 생성·자동 승인.
월간·연간은 카드가 등록되는 구독이라 기간마다 자동 결제되고, 앱이 만료 7일 전에 새 키를 받아 와 자동 연장합니다.
카드 정보는 Lemon Squeezy 결제창에서만 입력돼요. SystemBoost 앱과 서버에는 카드 정보가 오지도, 저장되지도 않습니다.
```
앱 '결제하기' → 주문 코드를 실은 Lemon Squeezy 결제창 → 결제 → 서명 확인된 웹훅
→ 키 자동 생성 → 주문 [승인] (기록에 '자동 승인') → 앱 팝업
```
앱은 키가 나올 때까지 기다립니다(처음 15분은 5초마다, 그 뒤 1분마다, 앱을 껐다 켜도 14일까지).
키는 매번 새로 만들어지고 서명돼서 같은 키가 두 번 나오지 않습니다.

**결제 준비 전에는 키가 나가지 않습니다.**
- 자동 승인은 결제 업체가 서명한 결제 확인(웹훅)이 올 때만 일어납니다. 수동 확인 방식에서 자동 승인은 없습니다
  (구매자의 '결제했어요'만으로 키를 주면 결제 없이도 키를 받을 수 있기 때문).
- 대시보드에 결제 링크가 없는 플랜은 앱에서 '결제 준비 중'으로 잠기고, 서버도 주문을 만들지 않습니다(503).
- 키는 판매자가 대시보드에서 '키 발급'을 누를 때만 만들어집니다.
- 자동 결제(Lemon Squeezy 웹훅) 경로의 판매 모드 기본값은 `off`: 웹훅이 와도 키를 만들지 않습니다.

## 관리자 대시보드 (`https://<서버 주소>/admin`)
| 기능 | 설명 |
|---|---|
| 실시간 사용 현황 | 지금 켜져 있는 앱, 오늘·7일·30일 사용자, 누적 설치, 켜 둔 시간, 프레임 생성 사용. 15초마다 갱신 |
| 다운로드 | GitHub 릴리스 집계: 설치 파일 전체, 오늘, 파일 종류별, 버전별 |
| 최근 30일 · 사용자 구성 | 일별 사용자 · 새 설치 · 다운로드, 플랜 · 운영체제 · 버전 · 국가 |
| 요약 | 사용 중 · 최근 30일 발급 · 만료 · 차단 · 전체 키 수 |
| 결제 방식 | 계좌이체 · 직접 결제(결제 링크가 있으면 켜짐) + 카드 결제(꺼짐 / 테스트 / 실판매) |
| 결제 신청 | 처리할 것(신청 중 · 결제 확인 요청) / 승인 / 거절 / 전체. 입금자명·메모를 보고 승인 또는 거절(사유 입력) |
| 키 발급 | 월간(34일) · 연간(369일) · 직접 입력(일). 주문 코드가 있으면 구매자 앱에 바로 뜨고, 없으면(선물·리뷰용) 키를 복사해 보내면 됨 |
| 결제 링크 | 플랜별 https 링크(프리미엄 3개, 울트라 3개). 비우면 그 플랜은 앱에서 잠김. 앱은 프리미엄 화면을 열 때 반영. 카드 결제(Lemon Squeezy)는 프리미엄만 |
| 키 직접 발급 | 기간을 고르고 '프리미엄 키 발급' 또는 '울트라 키 발급'을 누름. 울트라는 프레임 생성 6·8배, 듀얼 GPU, 게임별 자동 최적화, GPU 오버클럭까지 열림. 앱에서 받은 주문을 승인하면 주문한 플랜의 키가 나감 |
| 발급된 키 | 메일 · 키 번호 · 주문 코드 · 메모로 검색, 상태별 보기, 키 다시 복사, 차단/해제 |
| 키 확인 | 구매자가 보낸 키를 붙여 넣으면 서명이 진짜인지, 차단됐는지, 언제 발급·만료인지 보여 줌 |
| 기록 | 발급 · 차단 · 링크 변경 등 최근 100개 (180일 보관) |
| 디스코드 공지 | 채널·알림을 고르고 글을 써서 미리 본 뒤 보내기. 템플릿, 보낸 글 수정·삭제(최근 50개). 아래 '디스코드 공지' 참고 |

**차단**은 앱이 인터넷에 연결된 상태로 켜질 때 적용돼요(`/check`). 오프라인 PC는 다음 연결 때까지 그대로 동작합니다.
구독 키를 차단하면 갱신도 멈춥니다. 자동 결제 환불(`order_refunded`)은 해당 키를 자동으로 차단합니다.

보안
- 대시보드는 `ADMIN_TOKEN`이 없거나 6자보다 짧으면 꺼져 있습니다(404).
- 비밀번호를 틀리면 잠깁니다: 같은 IP에서 5번 틀리면 15분, 전체 합쳐 한 시간에 20번 틀리면 그 시간 동안 잠김.
  6자리 숫자(100만 가지)를 한 시간에 20번씩 대입하면 수천 년이 걸려요. 대신 누가 일부러 틀려서
  잠깐 잠그게 만들 수는 있어요. 그럴 땐 기다리거나 `wrangler secret put ADMIN_TOKEN`으로 비밀번호를 바꾸세요.
- 비밀번호는 브라우저 탭 안(sessionStorage)에만 있고 탭을 닫으면 지워집니다. 페이지에 비밀 값은 들어 있지 않습니다.
- 관리자 API는 다른 사이트에서 호출할 수 없게(CORS 없음) 했고, 페이지는 CSP로 외부 스크립트를 막습니다.
- 더 막고 싶다면 Cloudflare Zero Trust Access로 `/admin*` 경로에 본인 메일 로그인을 추가하세요(무료 50명).

## 디스코드 공지 (`src/announce.js`)
대시보드 맨 아래, 또는 위쪽 '디스코드 공지' 버튼으로 갑니다.

- 웹후크 주소가 있으면 누구나 그 채널에 글을 올릴 수 있고, 이 저장소와 대시보드 페이지는 공개입니다. 그래서 주소는 코드에 넣지 않습니다.
- 대시보드 '디스코드 연결'에서 주소를 넣으면 KV `config:discord_hooks`에 저장됩니다. 저장한 뒤에는 어떤 응답과 기록에도 나오지 않고, 디스코드 호출은 전부 서버가 합니다.
- 저장할 때 웹후크를 읽어서 살아 있는지, 맞는 채널인지 확인합니다. 이때 글은 올라가지 않습니다.
- 보낸 글 목록은 KV `announce:hist`에 최근 50개까지 있습니다. 수정·삭제는 이 목록의 글만 됩니다. 웹후크를 새로 만들면 예전 웹후크로 보낸 글은 수정·삭제할 수 없습니다.
- 채널과 역할을 바꾸려면 `src/announce.js`의 `CHANNELS`, `ROLES`를 고칩니다.
- Workers 주소는 다른 사이트와 함께 쓰여서 디스코드가 잠시 막을 수 있습니다. 그때는 화면에 그렇게 나오고, 글은 올라가지 않습니다.

## 회원 (`src/accounts.js`, `supabase/accounts.sql`)
앱의 '계정' 화면에서 가입합니다. 회원이 아니어도 앱은 그대로 쓸 수 있습니다.
- 회원 정보는 Supabase(무료 플랜)의 Postgres에 있습니다. 앱은 이 Worker만 부르고, Worker만 비밀 키로 Supabase에 갑니다. 키, 추천 코드, 통계는 Cloudflare에 그대로 있습니다.
- 처음 한 번: Supabase SQL Editor에서 `supabase/accounts.sql` 전체를 실행하고, `wrangler secret put SUPABASE_URL`, `wrangler secret put SUPABASE_SECRET_KEY`를 넣습니다.
- 공개 키(publishable)로는 표도 함수도 닿지 않습니다. SQL 끝에서 이것을 확인하고, 다르면 오류로 멈춥니다.
- 아이디와 비밀번호로 가입합니다. 메일은 받지 않습니다. 가입할 때 복구 코드를 한 번 보여 주고, 비밀번호를 잊으면 그 코드로 바꿉니다.
- 비밀번호는 Worker에서 섞는 값(pepper)과 합친 뒤 DB에서 bcrypt로 저장합니다. 섞는 값은 서명 키에서 만들기 때문에 서명 키를 바꾸면 모든 비밀번호와 복구 코드가 끝납니다.
- 가입에는 개인정보 수집·이용 동의와 만 14세 이상 확인이 필요합니다. 동의한 시각을 저장합니다.
- 초대 코드: 회원이 앱에서 만듭니다. 그 코드로 가입한 사람은 프리미엄 3일을 받고, 초대한 회원은 한 명당 3일을 쌓아 앱에서 키로 받습니다(모두 30일까지, 코드당 50명). 숫자는 `src/accounts.js`의 `LIMITS`에 있습니다.
- 할인 티켓: 가입할 때 초대 코드를 쓴 회원은 10% 티켓을 받습니다(30일, 1회). 직접 결제 링크는 금액이 고정이라, 대시보드의 '할인 티켓' 링크(정가의 90%)로 보냅니다. 주문을 승인하면 쓴 것으로 처리하고, 거절하거나 지우면 돌려줍니다. 카드 결제에는 쓸 수 없습니다.
- 대시보드 '회원'에서 찾기, 차단, 복구 코드 재발급, 삭제를 합니다.
- 무료 플랜은 활동이 없으면 프로젝트가 일시 중지되고 백업이 없습니다. 매시간 작업이 Supabase를 한 번 부르지만, 어떤 활동을 인정하는지는 공개되어 있지 않습니다. 중지되면 Supabase 화면에서 복구합니다. 그동안 회원 기능만 멈추고 키 확인은 그대로 됩니다.
- 테스트: `npm i --no-save @electric-sql/pglite` 후 `node test_accounts.mjs`

## 추천 코드
대시보드 '추천 코드'에서 만듭니다. 코드, 메모, 플랜, 기간(1~30일), 사용 횟수 한도를 정하고 켜고 끌 수 있습니다.
- 앱의 프리미엄 화면에서 코드를 입력하면 `POST /referral`로 서명된 키를 바로 받습니다. 키는 키 목록에 메모 `추천 코드 <코드>`로 남습니다.
- 한 기기는 코드 하나만 한 번 씁니다(`refdev:<기기 번호>`, 90일 뒤 삭제). 기기 번호는 앱이 만든 무작위 값이라, 앱 데이터를 지우면 다시 쓸 수 있습니다. 코드별 한도와 하루 300개 상한이 그 위를 막습니다.
- 유료 키가 켜져 있으면 앱이 코드를 받지 않습니다. 짧은 키로 덮어쓰지 않기 위해서입니다.
- 코드를 나눠 준 사람의 보상은 자동이 아닙니다. 사용 횟수를 보고 직접 키를 발급합니다.
- 테스트: `node test_referral.mjs <임시 pem>`

## 사용 통계 (`src/stats.js`)
- 앱은 동의 후 `POST /ping`으로 무작위 설치 번호, 버전, 운영체제, 플랜, 프레임 생성 배수, 원클릭 부스트 여부를 보냅니다. 끌 수 있고, 무엇을 보내는지는 사용권 계약 제8조에 적혀 있습니다. 보내는 항목을 바꾸면 계약 문구도 함께 고치고 `Eula.Version`을 올려야 합니다.
- 저장 위치는 Durable Object(SQLite)입니다. 신호마다 쓰기가 생기는데 KV 무료 플랜은 하루 1,000번까지만 쓸 수 있어서입니다. `wrangler deploy`가 알아서 만듭니다.
- 신호 간격은 서버가 정합니다(그날 사용자 100명 미만 60초, 400명 미만 5분, 1,500명 미만 15분, 그 이상 1시간). Workers 무료 플랜은 하루 10만 요청을 넘으면 라이선스 확인과 주문까지 멈추기 때문입니다.
- 설치 번호는 마지막 연결 뒤 90일이 지나면 지워지고, 날짜별 합계는 남습니다. IP 주소는 저장하지 않습니다.
- 다운로드는 GitHub 릴리스 파일의 누적 횟수입니다. 매시간 cron과 대시보드가 가져오고, GitHub이 Workers 주소를 거부하면 대시보드를 연 브라우저가 대신 가져옵니다. `releases.*.json`과 `RELEASES`는 업데이트 확인마다 읽히므로 세지 않습니다.
- 숫자는 가짜 신호로 부풀 수 있습니다. 인증 없는 공개 주소라서입니다. 새 설치는 하루 3,000개에서 막습니다.
- 로직 시험: `node test_stats.mjs`. 실제 런타임 시험: `wrangler dev --local --test-scheduled`.

## 설치
1. `npm i -g wrangler` → `wrangler login`
2. `wrangler kv namespace create LICENSES` → `wrangler.toml`의 id 교체
3. 비밀 값 등록 (화면에 붙여 넣는 값은 아무에게도 보여 주지 마세요)
   - `wrangler secret put LICENSE_PRIVATE_KEY` ← systemboost-license-private.pem 내용 전체
   - `wrangler secret put ADMIN_TOKEN` ← 대시보드 비밀번호(6자 이상). 코드나 파일에는 적지 마세요
4. `wrangler deploy` → 나온 주소를 `wrangler.toml`의 `PUBLIC_URL`과 앱 `License.cs`의 `ServerUrl`에 넣고 앱을 빌드
5. `https://<주소>/admin`에 들어가 결제 링크를 넣으면 앱의 '결제하기'가 열립니다.

대시보드를 고쳤다면 `node build_admin.mjs`로 `src/admin_page.js`를 다시 만듭니다.
`admin/admin.html`을 파일로 바로 열면 가짜 데이터로 움직이는 시연 모드가 됩니다.

## 카드 자동 결제 — Lemon Squeezy
카드 등록 · 매달(매년) 자동 청구 · 환불 · 세금 처리를 Lemon Squeezy가 하고, 결제되면 웹훅으로 키가 자동 발급됩니다(판매자 확인 없이).
1. Lemon Squeezy에서 구독 상품을 플랜마다 하나씩(월간, 연간, 울트라 월간, 울트라 연간) 만듭니다.
2. 바탕화면 `SystemBoost 카드 결제 키 넣기.cmd`로 API 키와 웹훅 서명 비밀을 직접 넣습니다(`wrangler secret put LS_API_KEY`, `LS_SIGNING_SECRET`).
3. Settings → Webhooks에 대시보드 '카드 결제 설정'에 나온 주소를 넣고, 이벤트 `subscription_created`, `subscription_updated`,
   `subscription_payment_success`, `subscription_payment_refunded`, `order_refunded`를 고릅니다. 서명 비밀은 2번과 같은 값.
4. 대시보드 '카드 결제 설정'에 상점 번호와 플랜별 상품(variant) 번호를 넣습니다. 비워 둔 플랜은 카드로 팔지 않습니다.
5. 대시보드 카드 결제 '테스트' → 앱에서 '카드로 결제하기' → Lemon Squeezy 테스트 카드로 결제 → 키(24시간짜리)가 자동으로 뜨는지 확인
6. '실판매'로 바꾸면 실제 카드 결제가 열립니다. 테스트 모드의 상품 번호와 API 키는 실판매에서 쓸 수 없으니 실판매 것으로 다시 넣습니다.
   앱에는 사용권 계약의 카드 구독 조항(제3조 제3항)이 시행되는 2026년 12월 8일 0시(한국 시간)부터 나옵니다. 그 전에 '실판매'로 두어도 앱에는 카드 결제가 나오지 않습니다 (`CARD_LIVE_FROM`, src/index.js).

어떤 플랜인지는 Lemon Squeezy가 서명해서 보내는 상품 번호로만 정합니다. 결제창 주소의 custom 값은 구매자가 바꿀 수 있어서
주문 코드를 찾는 데만 씁니다. 첫 결제는 `subscription_created` 한 번으로 키 하나, 갱신은 `subscription_payment_success`(renewal)마다 새 키,
고객 포털에서 플랜을 바꾸면 `subscription_updated`로 바뀐 플랜의 키가 나갑니다. 첫 결제나 갱신을 환불하면 그 키를 차단합니다.
